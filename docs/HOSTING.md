# Хостинг и ежечасная замена серверов

Оба каталога обновляются сразу при запуске и затем раз в час. Это независимые задачи: `DEVICE_AUTO_UPDATE=1` для всего устройства и `PROXY_AUTO_UPDATE=1` для Telegram. Повторный запуск того же сканирования блокируется файловой блокировкой. Период отсчитывается от начала цикла, поэтому время проверки не добавляется к каждому часу.

Каждый текущий публичный сервер проверяется заново. OpenVPN должен установить настоящий туннель и выполнить HTTPS через него; MTProto — получить ответ Telegram `resPQ` с правильным nonce. Парсеры заново загружают источники и проверяют кандидатов. Работающий текущий сервер сохраняется; если он не проходит проверку, выбирается рабочая замена той же страны. Для новой страны выбирается самый быстрый проверенный кандидат. Россия остаётся обязательной для поиска в обоих режимах. Если рабочей замены нет, недоступная страна исчезает из выбора; чужой выход не выдаётся за российский.

Недоступные серверы без действующих профилей удаляются из каталога. Записи, на которые ещё ссылаются профили, хранятся как скрытые архивные записи: они не появляются в выборе и не выдают конфиг или ссылку подключения. Профиль показывает предложение подключить замену той же страны. После смены сервера старую запись удалит следующий цикл. На телефоне нужно импортировать новый `.ovpn` / `.conf` либо подтвердить новый прокси в Telegram: уже установленные сторонние VPN-клиенты и настройки Telegram нельзя обновить с сервера незаметно.

Если недоступен сайт-источник, проверяются сохранённые серверы и резервы. Если не работает сам Docker или отсутствует образ проверки, реестр не очищается: это сбой проверки, а не доказательство отказа всех серверов. Результаты проверки имеют запас свежести на время следующего сканирования. Текущие профили остаются бессрочными.

## Новый Linux-сервер

Нужен постоянно работающий Linux VPS с публичным HTTPS-доменом, Python 3.9+, Docker Engine и Caddy. У пользователя, запускающего приложение, должен работать Docker. Образы проверки обязательны для обоих режимов. Провайдер должен разрешать исходящие подключения VPN; проверки выполняются в отдельных контейнерах и не меняют маршруты самого VPS.

Из корня проекта подготовьте образы:

```bash
docker build -t northline-mtproxy:local -f deploy/mtproxy/Dockerfile deploy
docker build -t northline-openvpn-probe:local deploy/device-probe
```

Для новой установки используйте `.env.example` как шаблон `.env`. Укажите токен бота, постоянный `PUBLIC_URL`, свой `ADMIN_TELEGRAM_IDS` и `ALLOWED_TELEGRAM_IDS` (список ID или `*`, если доступ нужен всем). Сохраните `.env` с правами `600`. Шаблон использует отдельную папку `data/hosting`, не запускает Docker-серверы на Mac и не требует домашнего проброса портов. Реестры публичных серверов создаются автоматически после успешной проверки; свой WireGuard-сервер необязателен.

Остановите старый процесс с тем же токеном бота перед запуском хостинга. Запускайте проект через `python3 run.py`: он поднимает backend и бота, перезапускает их при сбое и сохраняет управление перезапуском из админки. Для запуска после перезагрузки используйте `deploy/northline.service` как пользовательскую службу systemd; она рассчитана на `~/northline`, при другом пути исправьте WorkingDirectory и ExecStart. Чтобы пользовательская служба работала без открытого SSH-сеанса, настройте linger для этого пользователя. Caddy проксирует ваш домен на `127.0.0.1:8000` по образцу `deploy/Caddyfile.example`; входящие 80/443 должны быть открыты.

Первое сканирование может занять несколько минут. Не запускайте дополнительные cron-задачи для тех же реестров: приложение уже проверяет их каждый час.

Для переноса существующих профилей переносите базу вместе с соответствующими реестрами, конфигурацией собственных узлов и ключами. Один только файл SQLite без реестров не подходит: приложение намеренно не запускается с потерянными серверами действующих профилей. Не публикуйте `.env`, базы, файлы конфигов и резервные копии в открытом репозитории.

## Проверка работы

Отчёты без секретов: `data/device-vpn-refresh.json` и `data/proxy-refresh.json`. В них есть `interval_seconds=3600`, начало и конец цикла, `next_check_at`, рабочие страны и удалённые из выбора ID. `partial` означает, что хотя бы один источник или обязательная страна не прошли проверку; подтверждённые рабочие серверы при этом применяются. `failed` оставляет прежний реестр при ошибке инфраструктуры или конфликте записи. `busy` означает уже выполняющееся сканирование.

Ручной одиночный запуск без бота и туннеля:

```bash
python3 -m backend.device_refresh
python3 -m backend.proxy_refresh
```

В локальном личном тесте домашние пробросы портов продлеваются отдельно каждые 15 минут; частота поиска публичных серверов остаётся один час. На хостинге с `PERSONAL_TEST=0` эта Mac-задача не запускается.

Постоянно сохраняйте `data`, фактические пути реестров и `registry-backups`. Временный адрес `trycloudflare.com` предназначен для локальной проверки; для хостинга укажите свой стабильный домен с HTTPS.
