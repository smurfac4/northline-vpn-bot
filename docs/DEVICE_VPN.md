# VPN для всего устройства: отдельный каталог

Режим **«Всё устройство»** получает публичные OpenVPN-конфигурации из [официального CSV API VPN Gate](https://www.vpngate.net/api/iphone/) и отдельного [российского списка VPN Obratno](https://vpnobratno.info/en/), публикующего VPN Gate-конфигурации TCP и UDP. Telegram/MTProto в этом режиме не используется.

**Россия обязательна** и показывается первой. Для РФ сохраняются до четырёх проверенных резервов с разными выходными IP в закрытом файле `data/device-vpn-reserves.json`. Добавление в российскую локацию допускается только после реального VPN-туннеля, HTTPS через него и подтверждения российского выходного IP.

| Назначение | Каталог | Клиент |
|---|---|---|
| Свой управляемый VPN | `nodes.json` | WireGuard, `.conf` |
| Публичный VPN всего устройства | `device-vpn-nodes.json` | OpenVPN Connect, `.ovpn` |
| Только Telegram | `proxy-nodes.json` | Встроенный MTProto в Telegram |

Профили и разрешения режимов независимы. Обновление публичного VPN-каталога не записывает `nodes.json`, `proxy-nodes.json`, MTProto-секреты или состояние Telegram-контейнера.

## Подготовка

Docker Desktop должен быть запущен. Один раз соберите проверочный образ из корня проекта:

```bash
docker build -t northline-openvpn-probe:local deploy/device-probe
```

Настройки `.env`:

```dotenv
DEVICE_AUTO_UPDATE=1
DEVICE_NODES_PATH=
```

По умолчанию обновление включено, каталог расположен в корне проекта. Он содержит общие публичные ключи оператора, сохраняется с правами 600 и исключён из Git. Для отключения задайте `DEVICE_AUTO_UPDATE=0`.

## Проверка при запуске

В `live` backend запускает независимую фоновую проверку при старте, затем каждый час. Если РФ не прошла проверку, поиск повторяется в следующем часовом цикле. Бот не ждёт окончания проверки.

1. Заново загружаются официальный список VPN Gate и российский список. Для российского источника разрешены только прямые `_ip_tcp.ovpn` / `_ip_udp.ovpn` на `vpnobratno.info/servers/`; ссылки на посторонние сайты, локальные пути и произвольные загрузки не используются.
2. Разрешены публичные IPv4, встроенные сертификаты и ограниченный набор параметров. Скрипты, плагины, локальные пути, интерфейсы управления и неизвестные директивы отклоняются. Обязательны проверка сертификата сервера и TLS 1.2 или новее.
3. Сначала проверяются до двух кандидатов на страну; если рабочего узла нет, проверяются ещё до четырёх резервных. Для обязательной РФ поиск расширяется до 32 кандидатов и продолжается до получения нескольких рабочих резервов с разными выходными IP. Текущий сохранённый узел и российские резервы имеют приоритет. Одновременно проверяется не более трёх узлов.
4. Временный контейнер с отдельной bridge-сетью устанавливает настоящий OpenVPN-туннель, затем выполняет HTTPS-запрос через `tun0`. Открытый порт не считается рабочим VPN. Маршруты и DNS Mac не меняются; контейнер после проверки удаляется.
5. Страна проверяется по фактическому выходному IP. Для каждой подтверждённой страны выбирается один узел с меньшим временем HTTPS-ответа среди проверенных кандидатов. Это не замер максимальной скорости.
6. Каталог обновляется атомарно. Узел с активным старым профилем сохраняется в архиве; для новых профилей он скрывается. Не прошедшая проверку старая запись отмечается как недоступная и не выдаёт новые профили.

Отчёт без ключей: `data/device-vpn-refresh.json`; поле `required.RU` показывает `verified`, `unavailable` или `missing`. Обновление не помечается как полностью успешное без проверенной РФ. Предыдущий каталог сохраняется в `registry-backups/`. Если источник недоступен, проверяются сохранённые узлы и резервы. Ручные изменения, внесённые во время проверки, не перезаписываются. При недоступности всех российских узлов локация убирается из выбора до появления проверенной замены, а зарубежный выход не подписывается как РФ; бесплатные чужие узлы не дают гарантии непрерывной доступности.

Разовая проверка без запуска бота, HTTPS-туннеля и постоянных тестовых серверов:

```bash
python3 -m backend.device_refresh
```

## Подключение

Откройте **«Всё устройство»**, выберите локацию с протоколом **OpenVPN**, создайте профиль и откройте настройку. Скачайте `.ovpn`, импортируйте его в OpenVPN Connect и включите VPN. Через `/config` в боте также доступна выдача файла. После смены сервера импортируйте новый файл.

Проверяется выход по IPv4. При наличии IPv6 используйте блокировку IPv6 в настройках OpenVPN Connect, чтобы он не шёл мимо IPv4-туннеля. Для Linux нужен совместимый клиент OpenVPN.

VPN Gate — публичные серверы внешних операторов, которые [ведут журналы подключений](https://www.vpngate.net/en/about_abuse.aspx). Конфигурации общие: удаление профиля или окончание срока в боте закрывает выдачу в боте, но не отзывает файл у оператора. Для отключения выключите VPN в OpenVPN Connect. Это сообщение также показывается в настройке публичного VPN-профиля.

Свои WireGuard-узлы продолжают выдавать `.conf` и управляться по SSH независимо от публичного списка.

## Кнопки подключения в Mini App

После выбора устройства первая кнопка ведёт к официальному клиенту для текущего протокола. Telegram не предоставляет сведения об установленных приложениях: отметка «Уже установлено» задаётся пользователем и сохраняется отдельно для аккаунта, платформы и протокола. После отметки кнопка предлагает открыть клиент. На iPhone/iPad установленный OpenVPN Connect открывается ссылкой `openvpn://` в новом окне: Telegram передаёт её внешнему обработчику iOS. Открытие не требует перехода в магазин; iOS может запросить подтверждение. WireGuard открывается через страницу App Store с кнопкой «Открыть». Для WireGuard на macOS также используется App Store, а на Windows/Linux показан способ ручного запуска.

Вторая кнопка — «Импортировать конфиг». На iPhone/iPad она через WebApp.openLink с try_browser=safari открывает отдельную HTTPS-страницу. На ней пользователь нажимает «Открыть OpenVPN Connect» и подтверждает открытие iOS: переход требует нового нажатия, автоматической переадресации нет. На этой же странице есть скачивание `.ovpn` для импорта через «Файлы» / «Поделиться». Страница проверяет тот же временный доступ, что и конфиг; ключи в HTML не включаются, токены обеих ссылок скрываются в HTTP-логах. OpenVPN Connect использует [официальную схему импорта](https://openvpn.net/as-docs/v3/token-url/) `openvpn://import-profile/https://…`. Ссылка выдаёт только конфиг текущего профиля, действует до пяти минут, проверяет подпись и состояние профиля и перестаёт действовать после отзыва, смены профиля, запрета режима или перезапуска backend. В HTTP-логи токен не записывается. WireGuard получает `.conf` через системное меню файлов, если WebView поддерживает Web Share; иначе предлагается скачать файл и импортировать его в клиенте. Кнопка ручного скачивания остаётся доступной при ограничениях WebView.
